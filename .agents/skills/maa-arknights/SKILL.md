# 明日方舟日常

以本文件向上三级的目录为仓库根目录，保留完整仓库。先读 [运行说明](../../../docs/RUNBOOK.md) 与 [恢复说明](../../../docs/RECOVERY.md)。只在当前游戏和阶段已获授权时执行。

默认只走 MuMu；先读 [MuMu 路由与固定清单](../../../docs/MUMU-DAILY.md) 和 [证据命令](../../../docs/MUMU-EVIDENCE.md)。用 `python scripts/mumu_daily.py plan --game arknights` 及 `status` 检查计划、同账号旧账和当前状态。此入口不接管游戏输入，也不会替代受限 MAA 任务的现有门禁。

## 固定流程

1. 从仓库根运行 python scripts/daily_pipeline.py status、python scripts/daily_audit.py。北京时间 04:00 切日。核对旧工作副本与本副本账本；不能用新目录避开当天已执行记录。
2. 配置缺失时按 [README](../../../README.md) 初始化。下载只用 scripts/bootstrap.py 的 arknights 固定官方 release。默认预览，执行需显式 --execute；不覆盖原安装。
3. 准备启动用 python scripts/prepare_game.py --game arknights，获授权后加 --execute。核对官方服、MuMu 实例和 loopback ADB serial；检查真实进程、登录与当前画面。
4. TL-9 已关闭。没有用户新增的精确关卡授权、适配和当前可代理证据时跳过战斗，不运行曾指定 TL-9 的基础战斗命令，不耗理智；非战斗阶段独立核验。不自动换关。
5. 公招加急、全部基建、信用购买、领奖用 `scripts/ark_operations_v2.py` 单轮。若已有用户手动开出的六星槽且 v2 无法避开，不运行会接管该槽的整轮；只执行可独立安全验证的项目。先无参数预览，再 --execute --home-reviewed --home-evidence <五分钟内主页PNG>。不串联旧 operations、accelerated 或补打脚本。
6. 按任务/配置/版本、taskid+uuid 完整回调、SHA 和 worker 状态核验。加急结束后执行下方四槽补槽，再核验实际奖励页与资源；PNG 格式或回调完成不等于视觉验收。
7. 全部要求通过后用 scripts/finish-game.ps1 预览并关闭精确对应游戏/MAA，验证进程消失。仅在另有授权且无其他游戏/下载时处理模拟器。

## 资源范围

- 禁止源石、付费货币、理智药、抽卡和额外循环。
- v2 加急阶段的旧保护配置不变：高级资深、资深、支援机械，`force_refresh=false`。补槽阶段按下方规则处理 3、4、5 星，不再刷新或加急。
- times=4 是新招募上限，不是四张加急许可硬上限。v6.22.0 忽略 expedite_times；无外部并发招募时最多原有四槽加新四次。实际消耗需从资源差值确认。
- Normal 全设施换班收菜；无人机只加速 Money 贸易站；不补货、不加工/训练/更换助手、不赠送/交换线索。
- 信用优先招聘许可，排除碳、家具、加急许可，不越过黑名单强制购买。

## 加急后公招补槽（3、4、5 星）

1. **逐一核对四槽。** 加急轮完全退出后，再检查 1–4 号槽。运行中的不取消；「高级资深干员」出现时整槽留空，原标签不刷新、不提交。手动开的六星也不代加急或聘用。不要把准备开招界面或 MAA 的确认次数当成槽位已填。
2. **脚本计算而不猜标签。** 用当前 MuMu 国服画面上的五个标签及许可数运行 `python scripts/ark_recruit_refill.py --permits <招聘许可数> --tags <按界面顺序的五个标签>`。默认读配置指定安装的 MAA 国服招募表；可用 `--pool` 只读核验其他安装。先确认资源表与当前游戏版本匹配，表缺失、过时或标签不识别就停。配置 `config.example/ark-recruit-refill.json` 固定只允许 3/4/5 星、9 小时、每槽一张普通招聘许可、禁止刷新和加急。优先选标签保留时最低星级最高的组合；「资深干员」单独可纳入五星，「支援机械」不作为一星目标。不承诺普通标签不会被系统划掉。
3. **预约后才点一次。** 用 `mumu_daily.py` 的 `recruit-refill-slot-1` 到 `recruit-refill-slot-4` 一次一个：空槽用当前总览和同槽 9 小时确认图 `reserve`；同屏确认选号、选中标签、普通许可和报价后才点一次。再用最新总览 `verify` 对照同槽标签、倒计时与许可/龙门币差值。已计时、保留六星、许可不足用对应 `observe`。提交结果不明保留预约/未知，不重试、不另起 v2。
4. **收尾看四槽结果。** 正常结果应是四槽在跑，或明确有六星留空；不足或不明按槽报告。补槽规划和账本不会点击游戏，画面核对与单次提交仍由监督者负责。详细字段见 [证据命令](../../../docs/MUMU-EVIDENCE.md#明日方舟加急后公招补槽)。

## 中断

--status 只读。--resume <summary> 只接受当天绑定、已验证完成前缀后的纯 planned 后缀，同时要求 --execute 和新鲜主页证据。submitting/running/unknown、哈希变化或已存在执行产物一律停止，不删账解锁。STOP/超时只停止本次受控 worker，不泛杀 Python。

不得为了测试技能启动游戏。v2 的防重与审计有离线测试，也有监督锁屏 ADB 会话中完成非战斗阶段的实测；不代表下次冷启、战斗或三游戏无人值守全链均已验收。

锁屏时按 RUNBOOK 的“锁屏与分游戏就绪检查”执行：只用精确实例 ADB guest 证据，主页与阶段审核通过后才做日常。冷启动成功或标题画面不算就绪；不因宿主锁屏停止已可用的 ADB 路径，但不绕过任何其他门槛。不自动回退原生 PC，也不把其他游戏同样视为锁屏可用。

### 临时活动关不是默认关

例如 OS-7 只证明一次正常游戏内原生代理有效。没有当次明确关卡/时段授权，不换掉 TL-9；开打前核对当期**战斗**截止、当前确切普通关、代理状态、次数和自然理智，商店仍开放不等于还能打。用 [sanity-event-stage 监督账本](../../../docs/MUMU-EVIDENCE.md#明日方舟仅记录明确授权的短期活动代理) 记录，不把此流程当 MAA Fight 能力。旧活动截止或状态不明就停止。

可选只读 ADB 检查见 [MuMu ADB](../../../docs/MUMU-ADB.md)，不替换既有 MAA 连接、锁屏非战斗、证据或资源门禁。
