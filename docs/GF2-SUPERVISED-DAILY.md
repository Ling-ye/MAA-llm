# 少前 2：商城、班组、调度室与本期活动的监督入口

这些入口位于仓库 scripts/，默认只输出计划，管理审核、独占账本、截图哈希和人工结果。**没有自动点击、导航、购买、战斗或领取后端**；--execute 明确拒绝。现场由监督流程完成的事项不能称为脚本自动化验收。

三个旧适配器仍固定 v2.8.4，旧商城/班组禁用项保持原样。新监督入口预约时只接受 v2.8.6 已审阅资源；不调用 PrepareDailyTasks、PublicAreaDailyTasks 或混合商城队列，不改登录、窗口、安全设置和其他购买项。

## 入口与账本

从仓库根目录运行：

~~~powershell
python scripts/gf2_daily_free_gift.py
python scripts/gf2_daily_free_gift.py --status
python scripts/gf2_squad_daily.py --phase supply
python scripts/gf2_squad_daily.py --phase duty
python scripts/gf2_dispatch_daily.py --phase collect
python scripts/gf2_dispatch_daily.py --phase redispatch
python scripts/gf2_dispatch_daily.py --phase weekly --tier 25
python scripts/gf2_heatdeath_supply.py
python scripts/gf2_daily_additions_audit.py
~~~

商城、班组补给、班组要务、派遣领取、再次派遣、本期活动各自按北京时间 04:00 游戏日防重。周奖励以周期＋5/10/15/25档分别记账；没有“本周全部已领”标志。所有写入共用原 pipeline.lock。不能在空克隆中重跑或删除、改名、清空 attempt。

新增审计独立于旧 daily_pipeline / daily_audit，不自动改变旧队列。监督者每日须额外检查上述审计，旧 coordinator 的 closed 不能证明这些任务完成。

## 一次监督操作

1. 检查原账本、游戏日和当前页面。同日已完成、提交不明或已有 attempt 时不再提交。
2. 准备审核 JSON，见 config.example/gf2-supervised/。文件 review-templates.json 按入口存放合成模板：预约取 before，完成取 after，历史人工回执取整组；单档观察取对应对象。填写真实画面和时间，不照抄示例。PNG/JPEG须有实际 SHA-256，文件须在 scripts/ 运行目录内。审核文件可以放 config.local/；evidence.path 相对 scripts/ 解析。格式与哈希不证明文字语义。
3. 保持游戏前台，用五分钟内证据执行 --reserve --review <审核.json> --base <实际MAA目录> --game-exe <实际GF2_Exilium.exe>。它核验版本、资源指纹、PID/HWND/路径/实际客户区，并在人工操作之前独占落账；**不会点击**。窗口改变、STOP、共享锁或信息不清就停止。
4. 监督者真正操作前再次检查当前选中项、费用、次数和前台窗口；只提交一次。不能凭旧图、旧坐标、旧控件位置补点。
5. 保存不同的新证据，以 --verify --review <完成审核.json> 验收记录。已领状态用 --observe。历史人工完成且有完整前后证据时用 --record-manual --review <外部人工回执.json>：外层 source 必须为 external_supervisor，内含 before / after。它只记录事实，不声称过去做过实时窗口检查。
6. 提交后断线或结果不明用 --mark-unknown --reason <原因>。保留原预约与证据，不释放防重、不覆盖成成功、不自动重试。查清后另留人工报告；入口没有清账重跑功能。

实机窗口曾为1920×1080，保存的JPG是1280×720缩放证据。预约读取实际客户区，不按图片尺寸猜窗口。尺寸不同时须声明 scaled_evidence_confirmed；仅接受已审阅的这两种16:9尺寸。

## 商城每日免费补给箱

只认商城→品质甄选→周期礼包→每日礼包的「每日补给箱」。同一详情须同时核对选中标签、商品名、每日免费说明、真正免费/0、日限购1/1、余量1和对应购买控件。周礼包、活动礼包、每日晶条礼包、收费或含糊币种均停止。

领取后可能切到 **每日晶条礼包 ¥6**，购买按钮位置不变，卡片顺序也会改变。禁双击、重试、固定卡位和只识别“免费/购买”。提交后只由监督者切回同名免费箱核对日限购0/1、已售罄及余额/进度，不再点购买。21日进度回卷尚未验收；当前配对要求进度加1，回卷时须停止审阅。

上游完整商城入口会试周箱，购买确认只认通用“购买”，故不直接启用。

## 班组补给与每日要务

- 补给只处理已加入班组、来源「每日刷新」的明确单条「每日补给·五」。同名可有多条，须按领前状态、到期提示及截图建立 item_reference；列表行号不是永久身份。只领核对过的一条，不点领取全部。绿勾和当日领取记录共同核验，按钮消失不等于已领。禁尘烟前线补给、班组商店、加入/退出、成员操作与职位变更。
- 要务只记录已审阅的「每日要务IV」、39级敌人、全部歼灭。初始「开始作战」与部署「作战开始」是不同阶段。确认无费用/补体提示，人工核对当前阵容；不自动组队、换助战或切自动开关。
- 预约后用 --record-step --step deployment --review <部署.json>，再用 --record-step --step in_progress --review <在途.json> 记录阶段。不能倒序、跳回或再开战；断线记 unknown。
- 完成须有部署、任务完成/DW-4 每日要务IV、奖励及返回后的「每日要务已完成」证据。单张奖励图、回调或5/5阵容不够。单次战力/助战结果不能保证其他阵容成功。
- 已安装 v2.8.6 班组入口仅领取补给，未找到已核验的要务独立执行入口。上游 README 的功能描述不等于本机已适配。

## 调度室与本周派遣收益

领取、再次派遣分账，只处理已核对的原五队。一键领取后记录「派遣完成」，再用原「再次派遣」保持配置，核验5/5在途且逐队记录倒计时。不付费加速、不改阵容。已在途只观察，不因没有领取按钮而重派。

「本周派遣收益」是周进度档弹窗；主界面「调度收益」进入情报储备/资源生产，「调度考核」也不是该弹窗。本工具不领这些无关项目和神秘盒。

周档已领用 --phase weekly --tier <5|10|15|25> --observe --review <该档绿勾.json>。未解锁档用 --observe-pending，记录明确「未完成」及进度；它不占领取 attempt。之后解锁仍可单独预约，其他已领档不阻断。

周 key 仅按北京时间游戏日的日历周归档，**跨周不等于游戏已重置**。跨周首次须有新鲜、明确0次进度、无已领档及 cycle_reset_reviewed=true 的单独观察才启用新周期。无法核实重置则停止，不清除旧记录。周新解锁档实际领取尚未实测。

重派遮罩若看不到领前余额，写 null 和 currency_not_visible=true，结果明确 resource_delta_verified=false；不用领后值伪造前后相同。仍须监督原队重派没有费用提示。

## 热寂悖论的每日物资模式

独立入口 gf2_heatdeath_supply.py，只记录本期「热寂悖论→物资模式→DF-1-5 于乱流中 V」。最高已解锁、自律可用、三目标完成均须当次核对，不改走挑战/剧情/活动商店。关卡名字段统一在 V 前保留一个空格；这是人工审核字段，不是 OCR 识别能力。

只用当前已核实的活动专用「准入密钥」（库存上限6），不是普通情报或体力药。自律确认须同屏核对次数、每次1钥匙、总耗费和确认控件；次数只能等于当次现有钥匙且不超过实际 UI 上限，不补充、不兑换、不消耗普通体力/付费货币。当前只有一次3次批量流程的外部人工实测；其他数量、上限变化和自动输入均未验收。

战斗截止固定为2026-11-24 08:59北京时间；2026-11-30 04:59只是兑换关闭时间。到战斗截止即拒绝新预约，不能凭商店仍开放继续。活动首页、关卡、密钥详情和提交确认形成证据链；领后须有奖励名称/数量、完成批次数和零钥匙页面。奖励数量不能凭次数推算。

当前无钥匙或活动明确关闭，用 --observe-pending 记录有证据的跳过；不占尝试账本。活动状态不明则停止。无可靠活动识别后端，不能把人工完成归功于脚本。提交后不明仍保留 unknown，禁止重试。

## 验证边界

离线反例通过不等于可靠视觉识别或安全点击已实机验收。审核内容由监督者负责，不能伪填 supervised 或画面字段。单次人工成功只证明该次流程。

缺证据、哈希失配、窗口切换、收费/弹窗含糊和未知状态均停止。维护仅离线测试，不为测试重领、重派或开战。本地截图、账本、账号及成员信息禁止上传。
