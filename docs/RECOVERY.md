# 中断与恢复

默认 MuMu 不回退 PC。先读 [固定清单](MUMU-DAILY.md) 和 [证据命令](MUMU-EVIDENCE.md)，独立保存 guest 证据与未知提交；下文旧 Win32 故障排查仅在明确选择该路线时用。

## 通用判断顺序

1. 先检查 scripts/STOP、当前游戏日（北京时间 04:00）、协调状态、阶段 attempt 账本和明确引用的 summary，不猜“最新一个目录”。
2. 查已记录的 PID、实际可执行路径、对应任务/资源版本及真实画面。工具请求成功或 UAC 弹窗出现不能证明程序已启动。
3. 回执不存在、提交超时、进程仍在、submitting/running/unknown、哈希失配均表示需要人工核查；不重复提交。
4. 保留失败回执、请求、回调、日志和截图。不要删除 attempt、把它改名或初始化另一份目录来重试。
5. 只处理本次跟踪的子进程或对应 MaaEnd runtime，不泛杀 Python。STOP 文件留待解释原因后由操作者处置。
6. 画面异常、登录/协议/验证码/更新/UAC、未知资源消耗立即停止。不得通过改安全、显示、网络设置来解除阻塞。

## 方舟

ark_operations_v2.py --status 只读。--resume <summary> 只接受当天绑定的 schema=2 回执：
已完成前缀须通过配置/任务/结果/回调哈希、taskid、uuid 和 worker 状态检验，剩余阶段必须是 planned 且目录中只有 task.json。

~~~powershell
python scripts/ark_operations_v2.py --resume scripts/runs/<本次运行>/summary.json --execute --home-reviewed --home-evidence scripts/evidence/<新鲜主页>.png
~~~

submitting/running/unknown、完整流程已完成、计划目录已有执行产物、其他 accelerated attempt 都会阻止恢复。不能重跑旧 operations/accelerated，也不能再刷 TL-9 来弥补公招或基建未完成。

成功恢复会将恢复前完整 summary 按哈希归档到 recovery_history，再记录当前尝试结果，保留旧错误而不让它冒充本次结果。

回调次数不是加急许可或无人机消耗数量。通过实际资源前后值记录消耗；不能把 times=4 说成“最多四张加急许可”。

## 少前 2

旧脚本固定 MaaGF2Exilium v2.8.4；遇到 v2.8.6 必须停下。不要删除或改成宽松版本比较，不要导入 v2.8.4 的回执来认证 v2.8.6。
安全适配至少需审阅两版入口/资源/PC 覆盖及代理注册差异、验证禁用节点、补离线回归，再在新游戏日受监督验收。

喝茶、任务领奖分支和扫荡加号识别存在受监督边界。自动点击失败后保存当前画面与资源变化；只在明确新授权和可判断未执行范围内操作，不运行一次性历史坐标脚本。扫荡上限由当前自然/升级赠体力决定，不买体力、不使用接入密钥。脚本不能自动证明已选最高可扫荡突破关卡。

## 终末地

- 官方启动器白屏：保存阻塞信息，停止启动链。没有游戏进程和登录画面，不运行 bootstrap/daily；不直接运行 Endfield.exe 绕过启动器，不把重启次数当成成功。
- MaaEnd 必须真实运行且 API 报 elevated=true；用户处理安全桌面，脚本不会代点。
- exact resource hash 变化：停止，审阅新版本/资源。不要对当前文件盲目重新生成“安全基线”。
- 提交接口超时：认为任务可能已经开始，尝试停止本 runtime，保留 attempt；不重复 tasks/start。
- 100 活跃只属于核心日常。环境监测、AutoSell、AutoStockpile 各有独立 attempt、结果与视觉验收。
- 物资调度购买采用原生动态数量，没有独立验证的硬支出上限；禁止把稳定购买的保留阈值挪来当保证。额度不足时记录 no-op，不反复购买。
- 保留的 --recover-pretrade-parse-failure 仅适用已有实现能严格证明的 autosell 整数解析前交易错误：原回执/日志/截图/实例/日期都须绑定一致，日志只允许 scan_item 后 exact parse error，且仅另建一次恢复 attempt。任何可能已经成交、其他错误或证据缺失都不允许使用。

## 清理

先验收所有所需阶段，再预览清理。finish-game.ps1 会调用只读完成校验，在进程访问前检查当前日期、对应回执和全范围覆盖。方舟另外校验完整 v2 证据。

关闭失败时保持 pending，不强制结束无关进程。终末地仅旧 PC 路线用原生 CloseGamePC；MuMu 只核验并关闭准确的 guest 游戏包与关联助手，不把旧 PC 清理当作回退。模拟器退出需要确认无其他游戏/下载并有用户要求；本清理脚本不会关闭整个模拟器。

## 防重复的适用范围

互斥锁和账本作用于一个完整仓库副本。不要并行运行多个 clone、旧目录和新目录。升级时使用同一运行工作副本并保留本地运行记录；若必须迁移机器，先以只读方式核对历史，不把运行资料上传 Git。公开源码不包含历史运行状态，执行配置也默认关闭。

新增范围提交未知时保留独立 attempt，禁止重复装箱/购物/刷新；信用回退禁购任意商品。转交待接单不等于尾款到账，次日先检查领取。详见 [新增任务恢复说明](ENDFIELD-EXTRAS.md)。

## 新监督入口的中断

[少前2新增入口](GF2-SUPERVISED-DAILY.md) 与 [谷地三仓](ENDFIELD-VALLEY-TRANSFER.md) 将预约、阶段和未知提交写入独立账本；无自动游戏输入。提交后不明必须 mark-unknown，保留原画面与尝试，不重放。谷地已有报价不得重新装箱，部分装入与低库存不能写成已发布。周未完成档只是观察，不占日后解锁的领取尝试；跨周要有真实重置证据。
