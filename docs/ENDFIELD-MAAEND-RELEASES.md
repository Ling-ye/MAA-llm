# MaaEnd 新版兼容流程（显式 PC）

旧版完整执行器仍限定 v3.1.0 / MaaFramework v5.16.1。新版适配不改旧资源门禁，也不视为启用 MuMu、后台锁屏或恢复任何定时任务。

1. 核对官方 latest 正式发布（不是预发布），对比 `interface.json`、具体任务定义和识别节点、外挂进程配置及资源消耗分支。
2. Windows 先核对实际 MaaEnd 进程、安装文件和更新日志。**只读**运行 `python scripts/endfield_mxu_port.py --app <安装目录> --pid <核对过的MaaEnd进程号>`。仅检查属于该 PID 的本机监听；当安全退出不完整、旧进程占用 12701 时，新 MXU 可能退到另一个端口。回退端口不等于自动信任任意旧进程、版本或配置。不要结束无关进程或修改端口设置。
3. 先使用独立实例确认读取 1280×720 认证后的游戏世界，不能用标题、读条、月卡弹窗或连接成功作为主页。每次执行重查窗口、进程、锁和同游戏日账本。
4. `python scripts/endfield_mxu_basic.py` 默认只预览 v3.3.0 / v6.0.0-beta.3 的两项配置。现场授权、当前世界截图、已有可信执行目录及对应进程齐备才可显式执行。只含帝江号快收和已有奖励，不包含战斗、补体力、升级、合成、购物、主动交换线索或开启新交易。不得用空执行目录重跑。
5. 自动回调不证明活跃达 100。逐项核对奖励画面；其余区域任务、货物、购物和战斗尚需各自审核。不覆盖旧回执、不临时重签未知版本、不在提交结果未知时重试。

新版本先离线回归，再做只连接和截图的实机验证，最后从低副作用的阶段逐项验收。持续检查发布不等于自动更新安装或自动启用任务。


阶段 `--phase inventory` 仅能接续本适配器当日已成功的基础维护。它复用独立核验的目标库存策略，过滤新版已删除的三个旧节点，固定单倍奖励并禁用理智药分支；结束后只补领活跃度奖励，不重跑邮件、旧仓储尾款、通行证或活动领奖。此阶段另有账本，提交不明不得重试。区域、仓储新单、购物和每日定时没有新版验收。

## 收尾：完整验收后正常退出

默认预览：`python scripts/endfield_mxu_basic.py --phase close`。监督流程确认全部日常后调用同一入口的 `--phase close --execute`；附上原有 `--app`、`--runtime`、`--hwnd`、`--game-pid`、`--maa-pid` 和 `--completion-proof <审核JSON>`。不能把只执行「帝江号」或「协议空间」的回调成功当作完整日常。

审核 JSON 放在同日 inventory 回执的目录内，包含：

- `game: "endfield"`、`game_day`（北京时间 04:00 切日）、`visually_reviewed: true`。
- 确认当前游戏内活跃度 100 且五档都已领后，填写 `activity: 100`、`claimed_tiers: [20,40,60,80,100]`。
- `screenshot` 为该运行目录内最近五分钟截图的文件名，`screenshot_sha256` 为该 PNG 的散列；`summary_sha256` 为原封不动的 `summary.json` 散列，`game_process` 取自这份 summary。此处需要人工看清游戏画面，不是 OCR 自动证明。
- 环境监测、物资调度、仓储、信用、回收等额外项目仍须通过同日全量审计；部分完成、错误或证据不明时不发退出消息。

全部通过后，只向同一启动实例的 Endfield 游戏窗口发送一次正常关闭请求，实际等到该进程退出才记为关闭。不强制结束、不重试不明请求、不关闭 MaaEnd、启动器或其他游戏。旧回执若未记录启动进程身份，不能追认或伪写；关闭当前流程未做真实满档验收，退出行为由离线测试覆盖。
