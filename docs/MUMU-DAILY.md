# MuMu 三游戏日常：路由与固定清单

三款游戏默认走 Windows 主机上的独立 MuMu Android 客户端。PC 旧路径仅在明确选择（有该参数的旧入口显式使用 `--transport pc`，PowerShell 用 `-Transport pc`）且符合各自门禁时可用；MuMu 阻塞时**不自动回退 PC**、不换模拟器实例、不换账号或渠道。下文是监督执行顺序，不是一键运行命令。

| 游戏 | 默认方式 | 已验证与未验证 |
| --- | --- | --- |
| 明日方舟 | 固定 MAA v6.22.0，经已核对的 MuMu ADB；基础与公招/基建/信用流程分开 | 曾验证 Windows 已锁的监督 ADB 会话能进入主页并运行；不保证以后每次冷启成功。TL-9 已结束，暂无授权替关，只明确跳过战斗、不耗理智；其他阶段单独核验 |
| 少女前线 2 | 用已明确绑定的官服 Android 客户端 `com.Sunborn.SnqxExilium`；MaaGF2Exilium v2.8.6 经 ADB，在监督下逐项核验 | 监督路径不依赖宿主桌面；锁屏须 [证明当前 guest](MUMU-ADB.md)，不宣称完整锁屏/无人值守。不要复用 v2.8.4 的 PC 入口或坐标 |
| 明日方舟：终末地 | 独立 MuMu 官服 Android 客户端；只在账号、主页和具体安全任务已核验后进入对应阶段 | 曾安装并到达启动/协议界面；此路径未验收登录后的工作流、锁屏或无人值守。不得把 PC 的 MaaEnd/Win32 路径搬来执行 |

## 执行前：逐游戏、逐阶段核验

1. 先正常处理游戏协议和账号登录；这些不由脚本代办。记录来源、服务器/渠道、运行方式，以及同一账号在 PC 和 MuMu 的当日实际状态。
2. 逐个运行。使用已配置的独立 MuMu 实例及其精确 loopback ADB serial；核对 guest 已正常启动、serial 精确一致、目标官方包存在、前台归属和可解码的新鲜 guest 帧。标题、黑屏、协议、安全或登录弹窗不是已登录主页。锁屏条件下，用当前 guest 画面和无消耗的响应验证，不借宿主窗口输入、绕过 Windows 锁定或改安全设置。
3. 先看计划、配置门禁和既有 ledger。游戏日以北京时间 04:00 归档，各界面实际重置和可领状态需现场核对；空克隆、空账或换运行方式不允许重复提交。不同阶段可能共用游戏资源，版本不符、账号不清、前台不清、未授权、已在途或响应未知，按实际情况停止或记录，不盲点。
4. 检查 [证据命令与字段](MUMU-EVIDENCE.md)。`scripts/mumu_daily.py` 是监督账本，不点击、不驱动游戏；其位置参数是 `plan`、`status`、`reserve`、`verify`、`observe`、`mark-unknown`。先在仓库根目录运行只读预览：

~~~powershell
python scripts/mumu_daily.py plan --game arknights
python scripts/mumu_daily.py plan --game gf2
python scripts/mumu_daily.py status --game endfield
~~~

按计划输出选择实际项目 key。写入操作按命令帮助及证据文档传 `--item` 与需要的 `--review` JSON；`mark-unknown` 另填 `--reason`。满足本地执行开关以及该项目现场审核后才可预约。预约成功也不是游戏操作成功。操作者随后只提交一次，拿新证据核验；只看到既有完成、不可领或受限用相应 observation 记录，结果不明保留 unknown，不重试。旧计划、回调和审计不能代替此处证据，反之亦然。

## 明日方舟：基础与非战斗

- 先核验当前指定关卡是否开放且可代理。TL-9 已关闭；未明确授权其他关卡时，记战斗未执行，不填假收据、不另选关、不耗理智。
- 临时普通活动关只走当次获授权的原生代理，先核实可代理及战斗截止，再按自然理智预算；sanity-event-stage 只为监督留证。没有常驻备用关，也不能从旧活动奖页推断还可作战。
- 基础奖励、好友等只走已核验的基础路径；公招→全设施换班收取→信用领取/购买→日常领奖用独立 v2 审核。加急轮保护高级资深、资深、支援机械；加急结束必须用 [方舟 Skill](../.agents/skills/maa-arknights/SKILL.md#加急后公招补槽345-星) 独立逐槽补招 3/4/5 星，六星留空、不刷新、不提交；无人机只加速贸易站；信用遵守优先级和排除项。禁止自动补理智、额外战斗或强化来凑奖励。
- 分项目记实际完成、奖励页面、资源变化和遗漏；非战斗可单独完成，不冒充齐全。另见 [运行说明](RUNBOOK.md#明日方舟)。

## 少前 2：下面各项独立验收

- **基础与突破：** 分别核对每日活跃及全部可领奖档。只扫当前确认已可扫荡的最高人形突破材料关；开放或达到等级不等于首通/可扫荡。扫前确认关卡、次数、单次与总成本、实际自然/升级赠体力；不用药或付费补充。
- **活动层：** 分开记录真正免费的烹调首份、茶饮、已有花浇水，以及委托中的对应休憩奖励。进休憩大厅后，只认茶饮吧台旁实际出现的「茶歇一刻」，不点击远处浮标。红枣茶 Lv4 需看到制作确认同名、今日剩余一次且无费用；制作后同时核对「饮品加成」文案、蓝亮茶杯及任务 1/1。菜品加成不是茶饮证据。浇水可从「委托 → 绿意栽培」进入，只浇现有花，不播种、不换花。画面、触控尺寸及交互锚点重新核对，不重放旧移动坐标。
- **商城：** 日包是「品质甄选 → 周期礼包 → 每日礼包 → 每日补给箱」。周包另走「臻品礼包」中的「周周乐补给箱」。逐个核对精确标题、明确免费、当前剩余限购和购买控件；成功后可自动切到付费邻项，严禁双击/坐标重放。周箱只按实际周额度领取一次，日箱不替代周箱。
- **班组：** 单独核验每日要务、每日免费补给、以及「要务补给·一」。只领取当前可领且身份明确的单项，查看绿勾/领取记录，禁一键把其他班组项目纳入。
- **派遣与调度：** 调度室五队领取、沿原编成重派、逐档核对「本周派遣收益」；在途勿重派。跨周先见游戏实际零进度和未领奖档，再领可能改变周进度的收益。批量突破扫荡前另查「委托 → 调度」的储存情报拼图和资源生产：核对余额、仓储量及上限，免费快取/收取后分别核验；不得把派遣或周档当作这项的收据，亦不购买或加速。
- **旧热寂专项：** 只在「热寂悖论 → 物资模式 → DF-1-5 于乱流中 V」战斗仍开放、有已核实专用准入密钥、该关可自律时执行；用现有钥匙，不补充、无普通体力/付费货币。战斗关闭、无钥匙或状态不明就不要开战，不替换活动，商店截止不是战斗截止。其他已授权免费签到/战前补给按确切活动页和当前可领状态独立记录。

零体力活动仅当次明确授权。当前已审「直播重连世界海」物资自律与其他逐关模式都走[零体力专项](MUMU-EVIDENCE.md#少前-2仅当次授权的零体力活动)，结束时间、额度和回执独立核对，不混入日常自动任务。

旧 PC 监督入口有更窄的工具限定（见 [少前 2 原监督入口](GF2-SUPERVISED-DAILY.md)）；其日志不是 Android 阶段的已验收证明。

- 烹调：休憩大厅「美味烹调」→「常规菜品」→ 芝士烤土豆首份免费 → 黄色「下一步」→「确认邀请」。看任务 1/1 加实际菜品加成；只有核对当前常规栏确实无法免费制作才记不适用，档案升级和创意/自研为空不作依据。

**主线另算：** 仅在明确要求时推进，逐关绑定难度、费用/体力、胜负和下一关解锁；已结算不重打。普通关零费用的观察不推广到其他难度；困难上一章满星也不能推定下一章已解锁。使用实际章节图和锁定提示，不猜等级门槛。章内红色「英雄」可能只在进入主线章节后出现，不等于困难或同名限时活动。英雄首通后仅在同一关切回普通实证已结算时不重打，检查后恢复原设置；困难仍独立核验。详细交接见少前 2 Skill；本仓不提供 MuMu 主线自动执行。

## 终末地：核心、环境、调度、仓储和回收分列

- 核心：只按受审库存/路线和单倍领取，核对核心日常奖档。两处已知环境监测终端各自查看新事项、计时与收录/回执；已收录不算当日新增。
- 物资调度：独立核对两地区出售和弹性购买，只按现行策略，保持原阈值和禁止项；仓储任务不替代物资调度。
- 四号谷地礼物：只买当次确为 **-80%** 的批准礼物，逐项检查库存、数量、费用、余额和回执；不扩大到其他稳定购买。
- 仓储：先看两区历史转交状态和明确可领尾款，再考虑箱子。匹配节点、货物、报价与已有委托，已有报价复用；四号谷地三节点分别记账。只按当前批准范围装箱并选择 **快速转交**，不走车/导航、不把待接单和定金当尾款到账。长期无人接单可能由协助者完成，行消失或超过计时不证明尾款已领/过期。武陵只在独立已授权且证据足够的路径做相应检查。
- 信用商店：先领信用，再以嵌晶玉/武库配额为优先；仅按配置的预算与刷新范围，核对品名、价格和余额，刷新一次便重查货架，不购买未知/超预算目标。两区资源回收分别远程收取并核验。
- 不耗付费货币、理智药、双倍许可；不加据点交易、销毁/拆解、账户/UID 上传或其他未批准的支路。目标库存、核心奖、两个终端、物资出售/购买、礼物、各节点、尾款、信用和回收应分别记录；100 活跃不替代这些凭据。

## 收尾

只关闭当前已核对的游戏及其受控工作进程；确认没有误关其他程序。是否关闭专用 MuMu 需另按约定且确定无其他作业；不要泛杀模拟器、Python 或 ADB。留下实际未完成项及原因。具体异常见 [恢复说明](RECOVERY.md)，完整验收状态见 [验证边界](VALIDATION.md)。
